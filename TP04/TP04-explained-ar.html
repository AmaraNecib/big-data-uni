TP04 / Docker · شرح من ملف الأستاذ

لماذا أنشأنا ثلاثة containers؟

اقرأ هذه الفكرة أولاً: الأستاذ طلب ثلاثة containers للتدرّب على تشغيلها وربطها بشبكة. لم يطلب تقسيم معالجة الملف على ثلاث آلات.

هل تفعل نفس الشيء؟

نعم، الثلاثة في تنفيذنا تؤدي نفس وظيفة العرض التجريبي: تبقى شغّالة وتستطيع الوصول إلى نفس CSV. لا واحدة منها تشغّل تحليل البيانات حالياً. التحليل شغّلناه بشكل منفصل داخل container اسمه tp04-analysis باستخدام Docker Compose.

١. ماذا يريد الأستاذ فعلاً؟

عنوان العمل هو Containerization and Big Data Environment Deployment Using Docker. الفكرة هي أخذ برنامج تحليل بيانات ووضع بيئته داخل image، نشرها، ثم تشغيلها بأكثر من طريقة. هذا ليس تمريناً على بناء distributed cluster.

  1. Task 1 — Installation: التأكد من تثبيت Docker وإنشاء حساب Docker Hub.
  2. Task 2 — Image: إنشاء image، رفعها إلى Docker Hub ثم سحبها.
  3. Task 3 — Containers: إنشاء ثلاثة containers من الصورة المسحوبة، ربطها بشبكة، والتحقق من تشغيلها.
  4. Task 4 — Compose: كتابة compose.yaml وتشغيل التطبيق مع ربط مجلد البيانات من الجهاز.
  5. Task 5 — Report: الإجابة عن أسئلة Docker وCompose، وتسليم الملفات مع screenshots وREADME.md على GitHub.

٢. النص الأصلي الذي يفسّر الثلاثة

Create three containers from the downloaded image.
Create a network to connect the three containers.

الترجمة: أنشئ ثلاث حاويات من الصورة التي سحبتها، وأنشئ شبكة لربط هذه الحاويات الثلاث.

Verify that the three containers are running correctly by executing the appropriate command.

الترجمة: تحقّق باستعمال الأمر المناسب من أن الحاويات الثلاث تعمل بشكل صحيح.

لماذا تبقى شغّالة؟

شغّلنا أمراً بسيطاً بـPython يطبع رسالة ثم ينتظر باستخدام time.sleep(3600). هذا يبقي كل حاوية حيّة لمدة ساعة لتظهر في docker ps ويمكن فحص شبكتها. هذه حاويات تجريبية مؤقتة، وليست خدمة تعمل للأبد.

تحقّقنا داخل كل حاوية من وجود الملف وحجمه، 6,463,485,112 bytes، ومن أن اسم tp04-node1 يُحلّ إلى عنوان IP عبر Docker DNS. هذا يثبت الوصول للبيانات وعمل اكتشاف الاسم على الشبكة، وليس وجود نظام تحليل موزّع.

٣. أين جرى تحليل البيانات إذن؟

في جزء منفصل من التمرين، Task 4. ملف الأستاذ نفسه يعرّف خدمة واحدة فقط باسم data-analysis:

services:
  data-analysis:
    build: .
    container_name: tp04-analysis
    volumes:
      - ./data:/app/data:ro
    restart: "no"

استخدمنا هذه الفكرة وأضاف تنفيذنا ربطاً آخر لحفظ التقرير على الجهاز:

./docker-report:/app/report
  1. docker compose up --build يبني الصورة ويشغّل tp04-analysis.
  2. البرنامج tp02.py يقرأ الملف كاملاً على مراحل باستخدام Pandas chunking، ثم يحلّله مرة أخرى باستخدام Dask.
  3. يحفظ النتائج في docker-report/ ثم ينتهي. الخروج بـcode 0 يعني النجاح، وليس عطلاً.
النتيجة الفعلية

عالجنا 75,000,000 rows. الطريقتان أعطتا نفس مجموع total_amount، وهو 516,607,678,312.78. لم نستخدم الحاويات الثلاث لتسريع هذه المعالجة.

قد يستعمل Dask عدة threads داخل حاوية التحليل. هذا مختلف عن توزيع العمل على ثلاث حاويات. لو شغّلت الأمر الافتراضي للصورة في ثلاث حاويات دون إعداد توزيع، فكل واحدة ستحلّل الملف كاملاً من البداية، أي ثلاث نسخ من نفس العمل، وليس ثلث الملف لكل واحدة.

٤. ماذا نشرنا في Docker Hub؟

نشرنا amaranecib/sales-bigdata-tp04:1.0. الصورة تحتوي على Python والمكتبات والبرنامج. ملف البيانات الكبير ليس داخل الصورة.

هذا يتماشى مع مثال الأستاذ الذي يستخدم bind mount. أي شخص يسحب الصورة يحتاج أيضاً إلى نسخة من CSV على جهازه ويربطها بمسار /app/data. السحب وحده لا ينزّل بياناتك.

ما دور الملفات التي أنشأناها؟
  • Dockerfile: يحدد بيئة Python، يثبت المكتبات، ينسخ البرنامج، ويحدد طريقة تشغيله.
  • .dockerignore: يستبعد البيانات والتقارير والملفات غير المطلوبة من build context.
  • compose.yaml: يصف حاوية التحليل وربط البيانات والتقارير.
  • tp02.py --skip-oom: يتجاوز تجربة تحميل الملف كله في الذاكرة، لأن آلية تحديد الذاكرة الأصلية خاصة بـWindows ولا تنطبق كما هي داخل حاوية Linux.
  • README.md: يحتوي على أوامر إعادة التشغيل وأجوبة أسئلة التقرير.

٥. ما الذي يحتاج انتباهاً قبل التسليم؟

التشغيل نجح، لكن هذا لا يعني أن كل شروط التسليم موثّقة.
  1. اختيار بيانات TP02 بدلاً من TP03. النص في Task 2 يقول “Create an image for dataset Lab 3 (TP3).”، لكن قسم المتطلبات يسمح ببيانات TP02 or TP03. استخدمنا ملف TP02 الذي طلبته أنت. إذا كان الأستاذ يقصد TP03 تحديداً، فهذا يحتاج تأكيداً منه.
  2. Port mapping. النص يذكر -p ضمن Task 3. لم ننشر منافذ، لأن البرنامج ليس خادم HTTP ولا يستمع على منفذ. تقنياً لا يحتاجها، لكن إن كان تقييم الأستاذ يتطلب مثالاً على -p، فهذا الجزء لم نعرضه بعد. الشبكة وحدها لا تستلزم -p، فهو يربط منفذ الجهاز بمنفذ الحاوية.
  3. Screenshots. حفظنا تقارير وملفات تحقق نصية. هذه ليست بديلاً عن صور الأوامر التي طلبها الأستاذ. لا تعتبر صور التسليم مكتملة لمجرد وجود مجلد screenshots/.
  4. GitHub. الرفع إلى Docker Hub تم، لكنه ليس رفعاً إلى GitHub. يجب رفع ملفات المشروع وREADME والصور هناك أيضاً. لم نثبت هنا إكمال هذا الرفع. لا ترفع ملف CSV بحجمه الكبير إلى مستودع Git العادي.

٦. كيف تشرح عملك للأستاذ؟

«جهزت صورة Docker لبرنامج تحليل بيانات Python، ورفعتها إلى Docker Hub ثم سحبتها. أنشأت منها ثلاث حاويات تجريبية على شبكة واحدة للتحقق من التشغيل والوصول إلى البيانات. بعد ذلك شغّلت التحليل في حاوية واحدة باستخدام Docker Compose. ربطت البيانات من الجهاز للقراءة فقط وحفظت النتائج في مجلد خارجي. لم أبنِ distributed cluster، ولم أقسّم الملف بين الحاويات الثلاث.»
